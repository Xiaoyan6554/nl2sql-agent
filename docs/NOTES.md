## 约定

  提交 `eval/question_ids.json`（索引、种子、源文件 SHA-256），满足不提交数据集原文的要求。

  行数超出上限则该题记为资源限制错误。后续演示服务单独添加展示 LIMIT。

### 用户需要弄懂的五个问题

1. **虚拟环境是什么？** 项目的依赖单独安装在 `.venv/`，由 `pyproject.toml` 和 `uv.lock` 管理。
2. **为什么不能提交密钥？** `.env` 保存本机配置，`.gitignore` 阻止正常 Git 提交它；`.env.example` 只留模板。
3. **为什么下载成功不等于数据可用？** `scripts/download_spider.py` 检查 ZIP 格式、必需 JSON 和每个 dev 数据库。
4. **如何防止压缩包越界写文件？** `extract_dataset()` 检查解压路径、符号链接和总大小。
5. **为什么现在没有准确率？** 真实数据和评测入口尚未就绪；`results/` 中没有实际运行结果，不能写数字。

## Phase 0 验收与 Phase 1 计划

真实最小验收结果见 results/baseline_5.json。只读校验、模型连通和结果落盘已通过。
1. 全量 gold 预检，避免把数据损坏当成模型错误。
2. 先运行十题记录 token 开销，再运行固定清单全量基线。
3. SQLite 无效 UTF-8 使用 surrogateescape 保留字节，比较时不做有损替换。
4. 固定模型请求名、温度、种子，记录返回名和代码提交；供应商别名不是不可变快照。

### 用户需要弄懂的五个问题

1. baseline.py 为什么只调用一次模型？这样才能作为改进的参照。
2. db.py 为什么同时使用 mode=ro 和 authorizer？文件只读与操作白名单是不同边界。
3. safety.py 为什么解析 AST？字符串匹配无法可靠识别嵌套语句和多语句。
4. run_eval.py 为什么使用 Counter？相同行重复出现也属于查询结果语义。
5. llm.py 为什么记录未知 token 为 None？接口失败时不能把未知费用当成零。

## 安全验收口径准备

安全测试分开报告 SQL 执行边界和真实提示注入探测。SQL 层用恶意模型输出检验数据库边界；
提示注入场景再调用真实模型观察最终 SQL。前者不能冒充模型天然能识别所有攻击。
安全用例使用单元测试数据库，既不替换 Spider，也不计入执行准确率。

### 真实安全探测发现并修复的问题

模型拒绝恶意请求时可能返回自然语言，其中的单引号使 SQLGlot 抛 TokenError。
最初只捕获 ParseError，导致探测中断。已将两类词法/语法错误统一转为安全拒绝，
加入回归测试并重新运行安全探测；首次失败日志保留在 work/safety.log。
